📖 模块简介

上一个模块教你怎么用 STL，这个模块往下钻一层，看标准库怎么实现的。 我们不抄一整份 STL，而是盯着六个最关键的地方：配置器怎么分配内存、vector 的三根指针怎么长、 list 的哨兵怎么绕、红黑树怎么变色旋转、哈希表怎么 rehash、迭代器和算法怎么配合。

每一章都是一个可编译、可运行的“探针程序”：用 sizeof、元素地址、配置器计数器、 bucket_count() 把内部状态打印出来。你看到的不是别人总结的结论，而是自己跑出来的证据。

🔧 读源码的四把工具

  • 先看成员变量： vector 三根指针、deque 一个中控器加两个迭代器、map 一个 header 加 size。数据布局决定行为。
  • 用调试器单步： 在 push_back 里断点看扩容前后指针怎么变，在 rehash 里看桶数组怎么换，比干读快十倍。
  • 写探针程序： 用 sizeof、&元素、配置器计数器、bucket_count() 把私有状态“打印”出来，本模块六章都是这么干的。
  • 对照 cppreference： 标准规定“保证什么”，源码展示“怎么做到”。先看契约再看实现，别把 _M_start 这种私有名字当标准。

📚 学习建议

  • 不要按头读到尾： 每章先跑一遍程序，看输出，再带着“为什么”去读源码。源码是用来查证的，不是用来通读的。
  • 抓住数据布局： 容器的一切行为都藏在成员变量里。先画指针图，再看算法，比一上来啃模板容易得多。
  • 版本差异要心里有数： 本模块以 libstdc++ 为主，扩容倍数、缓冲区大小、桶数序列都是实现细节；MSVC/libc++ 会不同，套路相同。
  • 每章练习都要做： 尤其是给红黑树补删除、给 MiniVector 补移动构造，这两道最能检验你是不是真看懂了。
  • 读源码别怕下划线： _M_、__ 只是实现保留名。先看类型和注释，再看函数名，最后才抠细节。

👴 老师傅的话

徒弟，能走到“读源码”这一步，说明你已经不满足于当 API 调用员了。这是好事，但师傅得先给你泼盆冷水：

读源码不是为了炫技，是为了少踩坑、选对容器、写出能推演性能的代码。 你知道了 vector 扩容会搬家，就不会在循环里存着迭代器还 push_back； 你知道了 unordered_map rehash 只废迭代器不废引用，就敢在合适的场景拿指针； 你知道了红黑树插入最多两次旋转，就明白 map 的有序不是白来的。

  • 先猜后证。 看到 vector 的 capacity 序列，先猜“两倍”，再写程序验证。带着问题读，比从头啃效率高得多。
  • 先布局后算法。 红黑树难，难在旋转规则；但节点里只有颜色、父、左、右。把结构画出来，算法就没那么玄。
  • 标准是契约，实现是手段。 map 保证有序和 O(log n)，红黑树只是 libstdc++ 选的手段。别把实现细节当标准。
  • 别想一次读完。 挑一个容器、一个函数，顺着调用链看到底，看懂就停。贪多嚼不烂。

最后一句：光看不动手，等于没学。 把每章的探针改一改——换个类型、换个数、换个坏哈希——输出变了，理解才真的长在你身上。
